# 产品矩阵页重写：覆盖矩阵

> 2026-11-03

## 意图

`/products/` 的唯一目的是让人**看懂我们覆盖什么** —— 不是卖东西，也不是产品货架。
成功标准：访客停留 30 秒后能复述三件事——覆盖哪些物理过程、覆盖哪些装置、以什么形态交付。

现状页面做不到其中任何一件：页头之后是两个结构完全相同的区块，每块是「h2 + 2~3 行泛泛正文 + 一行卡片」，
全页真实内容只有 CBaldur（外链）、托卡马克方案、场反位形方案，以及两张「更多 / 敬请期待」占位卡。
真正的骨架（8 类物理过程、5 类求解器、2 类装置、2 条交付路径、4 家合作验证）只存在于 `bp.pdf`，页面一点没用上。

## 现状诊断

- `CardGrid` 的 `repeat(auto-fit, minmax(260px, 1fr))` 把 3 张卡拉到约 375×120，卡内只有一行字，其余是空白。
- 两个区块完全对称，页面上没有主角；矩阵页比首页的产品区块还弱。
- 第二个区块下方空掉大半屏直接进页脚，全页没有出口。
- `more.mdx` / `more_service.mdx` 与真产品等权，点进去是只有一句「敬请期待」的空页。
- `site.matrix`（含 `url: '#'`）是死数据，无任何引用。

## 目标 / 非目标 / 反目标

**目标**

- 首屏（1440×900）内看到矩阵的表头与前几行，一屏内理解「行 = 物理过程，列 = 交付形态」。
- 每一行都有：过程名、一句话做法、状态标记、装置/案例证据。
- 支撑层（5 类求解器、国产算力 2.0×）与证据（中科院 / 华为 / 星能玄光 / 新奥）各出现一次，不重复。
- 375px 无横向溢出；窄容器下矩阵退化为「每个过程一张条目」，列名随格出现。
- 亮/暗两套主题：正文 ≥4.5:1、图形标记 ≥3:1；`prefers-reduced-motion` 下无位移入场。
- 页面有出口：一句「没列到的可以按需评估」+ 预约合作 / 产品文档两个入口。

**非目标**

- 不改 `service_tokamak.mdx` / `service_frc.mdx` / `cbaldur.mdx` 正文；它们只作为证据出口。
- 不做价格表、不做竞品对比表（BP 中的竞品与融资信息不上公开站）。
- 不改首页产品区块的结构与样式。删掉 `more_service.mdx` 后该区块自然少一张「更多」卡，属预期结果，不算改首页。
- 不引入新依赖，不改构建管线，不动全站 header / footer。

**反目标**

- 不能靠「更多 / 敬请期待」占位卡撑版面。
- 不能为了矩阵的完整外观编造未验证的覆盖（例如给 FRC 在全部过程上打勾）。
- 不能让窄屏矩阵变成需要横向拖动的满屏小字。

## 约束

- styled-components + 容器查询（`containers.shell` 与 `fromContainer`），不新增视口媒体查询。
- 只用 `index.html` 已定义的令牌（`--accent` / `--gold` / `--line` / `--font-mono` …），不新增色值；圆角保持 0。
- 事实来源只有 `bp.pdf`（17 页）与现有 MDX；BP 未覆盖的格子留白，不推断。
- SSR 与 CSR 输出一致：新组件不许有 `window` / `matchMedia` 分支。
- 门禁：`tsc -b`、`biome check`、`node --test webpack-plugins/*.test.ts`、`node scripts/prerender.mjs`。

## 方案

已选 **A：覆盖矩阵**（以物理过程为主轴）。

| 方案 | 取舍 |
| --- | --- |
| **A. 覆盖矩阵（采用）** | 一屏同时回答过程 × 装置 × 用法；代价是格子必须克制，窄屏要变形 |
| B. 装置优先 | 贴近客户问法（「我做托卡马克，你们能做什么」），但矩阵感消失，加装置线性变长 |
| C. 能力栈 | 讲的是「我们多强」，回答不了「我做 FRC，你们能算吗」 |

### 相对 A 的一处调整（已确认）

原方案列是「装置 × 交付形态」。我把它收窄成**两列「交付形态」**，装置与案例作为每行的证据标签。

原因：BP 只给了托卡马克的逐项案例，FRC 只有「形成 / 平稳 / 磁压缩」。按「过程 × 装置」填表会有一半格子没有依据，
填了就是编。收窄后矩阵仍然回答同样三个问题，而每一格都能指到出处。

## 页面结构（自上而下）

**1. 页头**（复用 `PageHeader`）
标题「产品矩阵」不变；描述从泛泛的「核心工具链」改成可核验的一句：`8 类物理过程 · 5 类求解器 · 2 类装置，标准产品与定制方案两条交付路径。`

**2. 覆盖概览带**（复用 `StatStrip` 的语言）
`8 物理过程` / `5 类求解器` / `2 类装置` / `4 家合作验证`

**3. 覆盖矩阵**（本页主角）

- 列：`物理过程` | `标准产品 · CBaldur` | `工程仿真方案`
- 8 行：平衡与位形 / 磁流体稳定性 / 输运 / 高能粒子 / 加热与电流驱动 / 密度极限 / 器壁与热负荷 / 破裂与缓解
- 每行左格：等宽编号 `01`–`08` + 过程名 + 一句做法；两个交付格：状态点 + 一句「怎么用」；行尾：装置与案例标签
- 图例一行：`● 已交付案例` `○ 按需评估` `○ 规划中`
- 语义：`<ul>` + 每行 `<h3>` + 两个带列名的块。**不用 `<table>`** —— 窄屏需要把行折成条目，
  对表元素做 `display: block` 会破坏表格语义，而这里每格本身就是短语而非数据单元格；
  用标题分节对屏幕阅读器更友好。宽屏靠 CSS grid 对齐出表感，窄屏自动堆叠。

**4. 支撑层**（矩阵的两条地基，横向两条带）

- 求解器：平衡 / 磁流体 / 输运 / 粒子-中性束 / 壁面 PWI，5 个等宽编号小格
- 算力：国产异构算力，典型算例最高 2.0×，与华为合作 200%
- 视觉上用一条 hairline 与矩阵底部连起来，不新增卡片样式

**5. 装置与证据**

- 托卡马克 → `/products/service_tokamak/`：高能粒子（香蕉轨道 / 鱼骨模）、VDE 晕电流、MGI 破裂缓解
- 场反位形 FRC → `/products/service_frc/`：形成 / 平稳 / 磁压缩全过程；与星能玄光合作，实验成本降 60%
- 证据行：中科院等离子体所（仿真-实验关键指标一致）、EAST 欧姆起动（Science Advances）

**6. 出口**（替代原来的半屏空白）
一句「没列到的装置或物理过程，可以按需评估」+ `预约合作` / `访问产品文档`。轻量，不抢矩阵注意力。

## 删除项（已确认）

1. 矩阵页不再渲染 `sections/*.mdx` 的正文。这两个目录页的 `title` / `description` 只用于表头，正文是泛泛的介绍，与矩阵重复。
2. `more.mdx` / `more_service.mdx` 两张占位卡从页面移除，文件一并删除，否则它们仍会被预渲染进 `sitemap.xml`，留下两个只有「敬请期待」的空页。
3. `site.matrix` 是死数据（且带 `url: '#'`），一并删除。
4. 删除后 `product_section` 这套机制失去唯一用途（`kind` 成员、`toKind` 分支、`productSections` 导出、`Frontmatter.section_key`、`ssr.tsx` 的过滤），一并清掉；`Frontmatter.product_section` 保留，首页仍在用它分组。

## 实施中发现的额外问题

`src/lib/meta.ts` 里 `/products/` 的 SEO 描述写的是「覆盖算力供给、平台管理与行业智能」——与本站无关的旧文案，会进 `<title>` 之外的 OG / meta description。本次一并改成与页面一致的说法。

## 事实核对：一张不能编的表

BP 里有、但**站内现有文案与之冲突**的两处：

- 首页写「10+ 知识产权数量」，BP 写「申请国家专利 3 项，软著 3 项」。本页**不引用**这个数字，只用 BP 能支撑的。
- 首页写「7 篇高水平学术论文」，BP 写「发表高水平论文 7 篇」——一致，可用。

## 数据与代码落点

- `src/content/product-matrix.ts`（新）：`processes`（8 条：`key/label/summary/saas/service/devices`）、`solvers`（5）、`compute`、`evidence`。纯数据 + 类型，可被 prerender 静态读取。
- `src/pages/ProductsPage.tsx`：重写为上述 6 段，不再遍历 `productSections`。
- `src/styles/matrix.ts`（新）：`MatrixList` / `MatrixHead` / `MatrixRow` / `ProcessCell` / `DeliveryCell` / `StateDot` / `SolverStrip` / `EvidenceRow` / `PageExit`。全部用 `containers.shell` 变形。
- 复用：`PageHeader`、`Band`、`Shell`、`Eyebrow`、`StatStrip`、`BtnLink` / `BtnAnchor`、`reveal`。

## 我的决定（不需要你回答）

- **状态只有三种**，没有「不支持」：`●` 已交付案例、`○` 按需评估、`○` 规划中。缺省即不列，不自我否定也不夸大。
- **不加扫描线 / 闪烁 / 实时刷新**。HUD 风格在 ui-ux-pro-max 里标注 `accessibility risk: high`（要求 4.5:1 对比、键盘可达、reduced-motion）；本页只继承它的等宽标注、编号、细线，不继承动效。
- **动效只用现成的 `reveal` 级联**（`$delay` 0–3），不加新 keyframes。
- **页头描述与概览带的数字写死在页面里**，不进 `site.ts`：它们是这一页的论点，不是全站事实。
